# Spec — brainstorm

> **Glossary:** [CONTEXT](./CONTEXT.md)
> **Reference:** `13_weave/demo/`（`demo/main.py`、`business/personas.yaml`、`weave_adapter/agent.py`）与 `13_weave/README.md` —— 演示「共享客观上下文 + 人设私有记忆隔离」模式，本特性将其反转。

## 1. Context

我们要解决的，是把一个「多个人设各自独立回答同一问题、记忆彼此隔离」的演示，升级成「多个人设围绕一个主题、按顺序接力发言、所有发言共享可见」的头脑风暴机制。目标用户是**发起人**：任何想在开题、产品决策、技术方案之前，先让一组不同视角的 AI 角色对撞想法、并随后阅读讨论记录提炼结论的人。

为什么是现在：现有 Agent 框架（weave）已经提供了「循环（Loop）」与「记忆（Memory）」以及命名空间级隔离，demo 也证明了多个人设可以并行作答。真正的缺口在于缺少一条**共享、按序**的协作循环——这正是头脑风暴需要、而 demo 没有的东西。本特性是在这个现成地基上补上「共享桌面 + 回合调度」。

已承诺的方案：以「会话（session）」为单位组织头脑风暴——一个**主题** + 一个**可配置的人设名单** + 一张所有参与者共享可见的「**桌面**」；人设按可插拔的调度策略接力发言（默认固定轮转，可选一个**路由者**人设负责路由与收敛）；会话按三种可选停止条件之一结束（固定轮数 / 收敛判定 / 手动停止）。先在后端把能力做全，且**配置、提示词、业务、框架、未来前端彼此解耦**。引擎设计为「**稳定内核 + 可插拔扩展点**」：角色、调度策略、停止条件、消费界面都是扩展点，未来分支（如 Web 论坛界面、观察者角色、新的调度策略）经扩展点衍生，无需改动内核。

追溯：本特性是 weave demo「共享客观上下文 + 人设私有记忆隔离」模式的反转——把隔离的个人会话流改成一条共享会话流；demo 的解耦原则（业务层零框架依赖、适配层是唯一接入点、全部来自 YAML、零硬编码）继续沿用。（本段亦承载 critic 的「Decision override」落点。）

## 2. Goals

- 让一组人设产出一段「围绕主题、按序接力、人人可见」的讨论，而非各自独立作答。
- 让人设名单、调度策略、停止条件都能通过声明式配置改变，无需改代码。
- 让头脑风暴引擎与具体框架、具体界面解耦，今天能由命令行驱动，未来能接前端而不返工。
- 让引擎支持「衍生」：角色、调度策略、停止条件、消费界面都是可插拔扩展点，未来分支（如论坛界面、观察者角色）可接入而不改动内核。

## 3. Non-goals

- 不重写/增强框架本身的 Loop、Memory、LLM 适配——那是依赖，不是本特性范围。
- 本迭代不让真人以参与者身份中途插入发言（「玩家」仅指人设；人只负责发起、观察、停止）。
- 本迭代不实现 Web 前端与观察者角色——作为「未来可衍生分支」保留（内核预留扩展点），不在本迭代交付。
- 不做通用闲聊 / 多轮问答——这是结构化的、有边界与停止条件的头脑风暴。

## 4. User stories

### US-01: 发起人开启一场头脑风暴

**As a** 发起人（Host）
**I want** 给定一个主题和一份人设名单即可开启一场会话
**So that** 一组角色能围绕该主题开始对撞想法

### US-02: 参与者按序接力发言

**As a** 参与者（Persona）
**I want** 在自己轮到时基于主题与历史发言
**So that** 讨论能持续推进而非各自独立作答

### US-03: 所有发言落到共享桌面

**As a** 参与者（Persona）
**I want** 每一次发言都对所有人与所有人设可见
**So that** 后续发言建立在完整讨论之上

### US-04: 路由者决定发言顺序与收敛

**As a** 路由者（Moderator）
**I want** 在每次发言后决定下一位发言者并判断是否收敛
**So that** 讨论有方向、并在恰当时点收敛成结论

### US-05: 发起人按停止条件结束会话

**As a** 发起人（Host）
**I want** 会话按选定的停止条件结束
**So that** 讨论有明确的边界与产出

### US-06: 发起人声明式配置会话

**As a** 发起人（Host）
**I want** 通过声明式配置改动人设、调度与停止条件
**So that** 无需改代码即可复用引擎

### US-07: 发起人经扩展点衍生新能力

**As a** 发起人（Host）
**I want** 通过扩展点接入新角色、新调度策略或新界面
**So that** 未来分支（如论坛、观察者角色）无需改动内核即可衍生

## 5. Acceptance criteria

### AC-01 (US-01) — happy path

**Given** 发起人提供了一个非空主题和一个包含至少两位参与者的人设名单
**When** 发起人启动会话
**Then** 系统创建会话、记录主题与人设名单，并确认会话已开始

### AC-02 (US-01) — error

**Given** 发起人准备启动会话，但主题为空
**When** 发起人尝试启动
**Then** 系统阻止启动，并告诉发起人主题不能为空

### AC-03 (US-01) — domain invariant

**Given** 发起人选择的人设名单在去重后不足两位参与者
**When** 发起人尝试启动会话
**Then** 系统阻止启动，并明确指出「一场头脑风暴至少需要两位参与者」

### AC-04 (US-02) — happy path

**Given** 一个进行中的会话，桌面上已有主题与若干历史发言
**When** 轮到某位参与者发言
**Then** 该参与者产出一条针对主题、并承接历史发言的发言，系统将其记录为下一条按序发言

### AC-04b (US-02) — error

**Given** 某位参与者在轮到发言时产出失败（生成超时或结果为空）
**When** 系统处理该次失败
**Then** 系统重试若干次，仍失败则跳过该参与者并记录，会话继续推进

### AC-05 (US-03) — happy path

**Given** 会话中某位参与者刚完成一次发言
**When** 下一位参与者读取桌面
**Then** 桌面完整、有序地包含此前每一次发言，并标注各自的发言者

### AC-06 (US-03) — authorization

**Given** 一个参与者属于会话 A，而会话 B 的桌面属于另一场会话
**When** 该参与者尝试向会话 B 的桌面追加发言
**Then** 系统拒绝写入，会话 B 的桌面保持不变

### AC-06b (US-03) — authorization

**Given** 一个参与者属于会话 A
**When** 该参与者尝试读取会话 B 的桌面
**Then** 系统拒绝读取，会话 B 的桌面内容不向该参与者暴露

### AC-07 (US-04) — happy path

**Given** 会话启用了路由者
**When** 某位参与者完成一次发言
**Then** 系统在路由时点调度路由者，由路由者自由选定下一位发言者，或宣布收敛（选谁发言的约束由路由者的人设描述表达，不硬编码在引擎内）

### AC-07b (US-04) — error

**Given** 路由者选定的下一位发言者不在人设名单内
**When** 系统解析该选择
**Then** 系统回退到固定轮转顺序选取下一位，并记录这次无效选择

### AC-08 (US-04) — cross-context

**Given** 会话启用了路由者，并配置为「收敛判定」停止条件
**When** 路由者结合桌面上的讨论状态（会话上下文）与配置的停止条件（配置上下文）做出裁决
**Then** 系统按路由者的裁决结束或继续会话，结束时给出结论

### AC-09 (US-05) — happy path

**Given** 会话配置为「固定轮数」停止条件
**When** 讨论跑完配置的轮数
**Then** 系统自动结束会话，并产出完整讨论记录

### AC-10 (US-05) — happy path

**Given** 会话配置为「收敛判定」停止条件
**When** 路由者宣布已收敛
**Then** 系统结束会话，并附带一份结论或摘要

### AC-10b (US-05) — domain invariant

**Given** 会话配置为「收敛判定」停止条件，但路由者始终未宣布收敛
**When** 讨论达到配置的最大轮数上限
**Then** 系统强制结束会话，并标注「未收敛」

### AC-11 (US-05) — happy path

**Given** 会话进行中，且配置为「手动停止」
**When** 发起人发出停止指令
**Then** 系统立即结束会话并保留当前讨论记录

### AC-11b (US-05) — domain invariant

**Given** 发起人发出停止指令时，恰逢某位参与者正在生成发言
**When** 系统执行停止
**Then** 系统等待该在途发言落桌后再结束，保证该发言不丢失

### AC-12 (US-06) — happy path

**Given** 发起人修改了配置（如人设名单、调度策略或停止条件）
**When** 发起人启动下一次会话
**Then** 系统按新配置运行，无需改动任何代码

### AC-13 (US-06) — domain invariant

**Given** 某位参与者的人设定义缺少角色描述
**When** 系统加载该配置
**Then** 系统拒绝加载，并指明该人设必须提供角色描述

### AC-14 (US-07) — happy path

**Given** 一个最小占位扩展（例如一个只回显名字的占位角色）已按声明式方式定义
**When** 该扩展接入会话并启动
**Then** 该扩展在会话中生效，且核心循环无需改动（观察者等真实角色留待未来分支交付）

### AC-15 (US-02) — domain invariant

**Given** 某位参与者已完成其本轮发言
**When** 该参与者再次尝试在本轮追加一条发言
**Then** 系统阻止该追加，并说明该参与者本轮的发言名额已用

## 6. Non-functional requirements

| Aspect | Target | Measurement |
|---|---|---|
| 每轮编排开销（不含 LLM 推理）延迟 p95 | ≤ 100 ms | 本地插桩 |
| 读取完整桌面延迟 p95 | ≤ 50 ms | 本地插桩 |
| 并发会话数 | ≥ 5 个会话互不串扰 | 并发冒烟测试 |
| 会话可靠性（可用性） | 已开始的会话 99.9% 不被意外中断 | 耐久测试（进程崩溃 / LLM 失败 / 超时 / 断连场景） |
| 一致性/耐久 | 每场会话 0 条丢失或重复发言 | 追加顺序不变量测试 |
| 可扩展性（新增分支） | 新增一个角色 / 策略 / 界面 = 0 处内核改动 | 内核边界由 design 定义后审查变更范围 |

## 6.1 Security / privacy

- **Data classification:** internal —— 头脑风暴记录可能包含未定稿的产品/技术推理，不宜对外公开。
- **Personal data touched:** 无 —— 人设均为虚构角色，不收集真实个人信息。
- **AuthZ/AuthN impact:** 会话之间按命名空间隔离——一场会话的桌面不被另一场读到或写入；参与者的发言能力限定在其所属会话内。
- **Abuse cases:**
  - 跨会话泄漏：某会话的发言出现在另一会话的桌面 → 系统按会话隔离，拒绝越界读取/写入。
  - 主题注入：恶意主题诱导人设泄露系统提示词或其它会话 → 主题按不可信数据处理，人设被其角色定义约束。
  - 失控放大：主题导致人设无限空转 → 停止条件与最大迭代上限兜底。
  - 冒名发言：某人设冒用他人身份 → 发言者由系统标注，不以发言内容自称为准。
  - 越权连发：同一人设在单轮内多次追加 → 轮次跟踪阻止轮外发言。
- **Security review:** Required —— 新的多角色生成边界 + 提示词注入面。

## 7. Metrics / KPIs

- **会话完整性** — baseline: 0（新特性），target: 100% 的会话零丢失、零重复发言。
- **配置即生效** — baseline: 改一个人设需改代码，target: 0 次代码改动即可增删/重配人设与策略。
- **每会话产出** — baseline: 0，target: 每轮至少产生 1 条不重复的想法。
- **单会话成本** — baseline: TBD，target: 一场 N 轮会话的 token 成本在预算内（测量计划：记录每场会话 token 用量）。
