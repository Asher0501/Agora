## Stage 2 — 新发现 3 项

1. **[stage-2] `summary.role` 可指向非产出角色（judge/picker），校验通过后运行时才崩** — `agora/config/validator.py:71,103-105`；`agora/relay.py:207`；AC: n/a（QG-1）。summary 只在 free_text 角色产出前注入（`relay.py:207` 仅 `_produce` 路径）；`summary.role` 为 judge（output=verdict）时，judge prompt 引用 `{summary.key}` 通过加载校验（`validator.py:103-104` 把 summary_key 加进该角色 identity），但 `LlmVerdictTerminator` 上下文不含该 key → 会话已落盘后 relay 抛 `agora.invalid_placeholder`。**决议：Fix now** — `summary.role` 的 `output` 必须为 `free_text`，否则加载时 `INVALID_CONFIG`（T30）。

2. **[stage-2] `roles[].output` 未校验为闭集枚举，拼写错误使角色静默消失** — `agora/config/schema.py:116`；`agora/relay.py:69-73`；AC: n/a（ADR-0005 / QG-1）。`output` 存任意字符串，仅 judge/picker 引用时做相等校验；`output: "freetext"` 通过加载、角色被 roster 过滤，无 free_text 角色的场景「跑」出 0 轮 `manual` 静默空跑。**决议：Fix now** — `output` ∈ {free_text, pick_next, verdict} 否则加载时 `INVALID_CONFIG`（T31）。

3. **[stage-2] AC-06 守卫在 relay 路径未武装（并发 relay 重复产出）** — `agora/relay.py:131`；`agora/adapter/repository.py:86-94`；AC: AC-06 / AC-15 / spec §6「0 重复发言」。`TURN_ALREADY_PRODUCED` 只在显式 seq 分支生效，relay 走 `max+1` 自动序号，两个并发 relay 同一 run 会重复产出（实测 stop.max=10 产 16 条）。**决议：Defer** — 单进程单会话单任务模型（sad §7）下不会发生；并发 resume 竞态非本轮承诺面 → 记 spec §8。
